# Self-contained desktop app

The current release is **T3 Attested.app**. Copy it to Applications and open it. The app bundles its verification runtime and public connection defaults. It starts and stops its own worker; no installer, separately installed Node, receipt or Login Item is required. Tailscale is still required to reach the private VM. Normal app replacement updates both T3 and its verifier.

The public defaults identify the VM/proxy addresses, expected TLS connection-key fingerprint, inference endpoint and provider identifiers. They contain no API keys, passwords, pairing tokens, conversations or device approvals. Existing owner-only `attestation-client.json` takes precedence and is never overwritten. New devices use the signed app's defaults without creating a separate settings file. Firmware and inference release approvals remain on each device and require native authentication.

Build the normal desktop artifact, then run `build-app.mjs APP SDK GUARD PUBLIC_POLICY NODE OUTPUT SIGNING_IDENTITY`. Use a clean source commit and pinned SDK checkout. The builder copies the complete app, removes the sender's data-home override, bundles the verifier/SDK/license notices, verifies runtime hashes and seals the app without re-signing official Node. Keep this personal package private because it contains public but personal VM addresses and a connection-key fingerprint. The current distribution is macOS Apple silicon and development-signed, not notarized. No Gatekeeper, quarantine or TLS checks are disabled.

The app retires the old installer-owned `io.elchiapp.t3attested.verifier` job before probing its port. Other healthy, externally managed verifiers, including the Pro's custom service, retain their ownership. Histories, pairings, approvals and existing data homes remain intact. Prior external runtime files are no longer used by a fresh bundled startup. The old installer recipe remains only for rollback/history; it is not the current release route.

Focused checks cover relocation without an installer receipt, bundled integrity/link rejection, platform executable names, startup/shutdown ownership and missing-versus-invalid local policy. Test the packaged worker and app startup from an isolated home before delivery. Native Linux/Windows distribution and physical Air acceptance require their own checks; portable runtime selection is covered by unit tests. This integration does not change server orchestration, providers or their wire protocols.
